# Тренажер практичних робіт МДДЕКМ

Вебтренажер для виконання восьми практичних робіт з дисципліни «Міцність та довговічність деталей та елементів конструкцій машин». Він призначений для здобувачів третього (освітньо-наукового) рівня, спеціальність G9 «Прикладна механіка», ВНТУ.

Тренажер працює в режимі контролю. Здобувач отримує від викладача номер варіанта (1–30) і виконує роботи покроково. Тренажер перевіряє кожен проміжний результат, пояснює типові помилки, виставляє оцінку за шкалою РПНД (до 25 балів за роботу) і формує протокол із кодом автентичності.

| ПР | Тема | Що відпрацьовується |
|---|---|---|
| 1 | Критерії Треска, Мізеса, Писаренка–Лебедєва | головні напруження, σ<sub>екв</sub>, запаси, вибір критерію |
| 2 | Механіка руйнування | K<sub>I</sub>, a<sub>c</sub>, σ<sub>c</sub>, межі ЛМР, ріст тріщини за Парісом |
| 3 | Втома | S–N, правило Пальмгрена–Майнера, Rainflow (ASTM E1049) |
| 4 | Імовірнісна модель ресурсу | статистика, параметри Вейбулла, B<sub>10</sub>, умовна надійність |
| 5 | Цифровий двійник вала | НДС, верифікація з МСЕ, асиміляція даних моніторингу, прогноз ресурсу |
| 6 | Агентний workflow у CAE | архітектура агента, Human-in-the-Loop, збіжність сітки, аналіз журналу |
| 7 | PHM-система | механізми деградації, датчики, агенти, моделі, RUL за індикатором здоров'я |
| 8 | ШІ в дисертаційному дослідженні | верифікація джерел, критика тверджень ШІ, академічна доброчесність |

Кожне завдання прив'язане до компетентностей РПНД (ЗК.01–04, ФК.01, 02, 04, 07, 08, 09). Протокол показує карту їх сформованості.

## Розміщення на GitHub Pages

1. Створіть на GitHub новий репозиторій, наприклад `mddekm-trainer`.
2. Завантажте в нього весь вміст цієї папки (кнопка **Add file → Upload files**), зберігаючи структуру: `index.html`, `assets/`, `.nojekyll`, `README.md`.
3. Відкрийте **Settings → Pages**. У розділі *Build and deployment* оберіть **Source: Deploy from a branch**, гілку **main** і папку **/(root)**, натисніть **Save**.
4. За 1–2 хвилини сайт стане доступним за адресою `https://<ваш-логін>.github.io/mddekm-trainer/`. Надішліть цю адресу здобувачам.

Тренажер не потребує сервера чи бази даних. Він також працює локально: достатньо відкрити `index.html` у браузері.

## Налаштування

Усі параметри зібрано у файлі `assets/js/config.js`:

- `variants` — кількість варіантів (за замовчуванням 30);
- `salt` — секретний рядок. Змініть його на початку навчального року, і всі варіанти всіх робіт згенеруються заново;
- `showReference` — чи показувати в кожній роботі довідку з базовими залежностями з методичних вказівок.

Після зміни `salt` перегенеруйте кабінет викладача з тим самим значенням (див. нижче), інакше ключі не збігатимуться.

## Як працює здобувач

1. Вводить ПІБ і групу, обирає номер варіанта, який видав викладач.
2. Виконує роботи в будь-якому порядку. Відповіді автоматично зберігаються в браузері.
3. Здає кожну роботу один раз. Після здачі бачить оцінку, розбір кожного завдання і графіки.
4. На сторінці «Протокол і компетентності» завантажує файл протоколу (`.json`) і надсилає його викладачу.

## Як працює викладач

Кабінет викладача — окремий файл `МДДЕКМ_Кабінет_викладача.html`. Його **не розміщують у репозиторії**: він працює офлайн на комп'ютері викладача.

- **Відомість групи.** Перетягніть у вікно всі отримані протоколи. Тренажер відтворить варіанти, переоцінить відповіді, перевірить коди автентичності і позначить підозрілі випадки: дослівні збіги чисел у здобувачів з однаковим варіантом, однакові текстові відповіді, роботи, здані менш ніж за 5 хвилин. Відомість експортується в CSV для Excel.
- **Протокол здобувача.** Натисніть ім'я в таблиці. Відкриються еталони, текстові обґрунтування для ручного оцінювання і поле коригування балу для кожної роботи.
- **Ключі варіантів.** Повний ключ для будь-якого варіанта і зведений ключ роботи для всіх варіантів (зручно друкувати).

## Обмеження, про які варто знати

Тренажер повністю працює в браузері, тому алгоритм обчислення еталонів міститься в коді сторінки. Технічно підготовлений здобувач може його знайти. Обмеження «одна здача» можна обійти, очистивши дані браузера. Код автентичності виявляє лише ручне редагування файлу протоколу. Для підсумкового контролю рекомендується виконання в аудиторії або поєднання з усним захистом роботи.

## Структура

```
index.html               сторінка здобувача
assets/css/app.css       стилі (світла і темна тема, мобільна версія, друк)
assets/js/config.js      налаштування і довідка
assets/js/core.js        генератор варіантів, оцінювання, графіки
assets/js/works/prN.js   вісім практичних робіт
assets/js/app.js         інтерфейс здобувача
```
